🏛️ Architecture Globale

LAXA est construit selon une architecture en couches classique pour un interpréteur de langage, avec une interface web moderne.

🌐 Frontend (HTML/CSS/JavaScript)

Interface utilisateur, éditeur de code, affichage des résultats

↕️

🔌 API REST (Flask)

Serveur web, routage, gestion des requêtes

↓

🔤 Lexer (Analyse Lexicale)

Conversion du code source en tokens

↓

🌳 Parser (Analyse Syntaxique)

Construction de l'Arbre de Syntaxe Abstraite (AST)

↓

⚙️ Interpréteur (Exécution)

Évaluation de l'AST et production des résultats

Principes de Design

  • Séparation des responsabilités : Chaque composant a un rôle bien défini
  • Pipeline de compilation : Traitement séquentiel du code source
  • API REST : Communication frontend/backend via JSON
  • Modularité : Composants indépendants et réutilisables
  • Extensibilité : Facilité d'ajout de nouvelles fonctionnalités

🔄 Flux d'Exécution

1️⃣ Saisie du Code

L'utilisateur écrit du code LAXA dans l'éditeur web et clique sur "Exécuter".

2️⃣ Requête HTTP

POST /executer
Content-Type: application/json

{
  "code": "variable x = 10\nafficher x",
  "entrees": []
}

3️⃣ Analyse Lexicale (Lexer)

Le code source est transformé en tokens :

"variable x = 10" → [
  {type: 'MOT_CLE', valeur: 'variable'},
  {type: 'IDENTIFIANT', valeur: 'x'},
  {type: 'OPERATEUR', valeur: '='},
  {type: 'NOMBRE', valeur: 10}
]

4️⃣ Analyse Syntaxique (Parser)

Les tokens sont organisés en Arbre de Syntaxe Abstraite (AST) :

NoeudProgramme
├── NoeudDeclarationVariable
│   ├── nom: "x"
│   └── valeur: NoeudNombre(10)
└── NoeudAfficher
    └── expression: NoeudVariable("x")

5️⃣ Exécution (Interpréteur)

L'AST est parcouru et exécuté nœud par nœud :

  • Création de la variable x avec la valeur 10
  • Évaluation de l'expression x → 10
  • Affichage du résultat : "10"

6️⃣ Réponse HTTP

{
  "success": true,
  "resultat": ["10"],
  "variables": {"x": 10},
  "tokens": [...],
  "entrees_requises": []
}

7️⃣ Affichage

Le frontend reçoit la réponse et affiche les résultats à l'utilisateur.

🔤 Lexer - Analyse Lexicale

Responsabilité

Le lexer transforme une chaîne de caractères (code source) en une séquence de tokens.

Types de Tokens

Type Description Exemples
MOT_CLE Mots réservés du langage variable, si, tant_que, fonction
IDENTIFIANT Noms de variables/fonctions x, nom, calculer
NOMBRE Littéraux numériques 42, 3.14, -5
CHAINE Chaînes de caractères "Bonjour", "Hello World"
BOOLEEN Valeurs booléennes vrai, faux
OPERATEUR Opérateurs arithmétiques/logiques +, -, *, ==, et, ou
SEPARATEUR Séparateurs syntaxiques (, ), [, ], {, }, ,
FONCTION_BUILTIN Fonctions intégrées afficher, lire, sqrt, len

Processus de Tokenisation

  1. Ignorer les espaces et commentaires
  2. Identifier les nombres (entiers et décimaux)
  3. Identifier les chaînes (délimitées par ")
  4. Identifier les identifiants et mots-clés
  5. Identifier les opérateurs (plus longs en premier)
  6. Identifier les séparateurs

Exemple de Tokenisation

Code:
variable x = 10 + 5

Tokens:
[
  {type: 'MOT_CLE', valeur: 'variable', ligne: 1, colonne: 1},
  {type: 'IDENTIFIANT', valeur: 'x', ligne: 1, colonne: 10},
  {type: 'OPERATEUR', valeur: '=', ligne: 1, colonne: 12},
  {type: 'NOMBRE', valeur: 10, ligne: 1, colonne: 14},
  {type: 'OPERATEUR', valeur: '+', ligne: 1, colonne: 17},
  {type: 'NOMBRE', valeur: 5, ligne: 1, colonne: 19}
]

🌳 Parser - Analyse Syntaxique

Responsabilité

Le parser transforme la liste de tokens en un Arbre de Syntaxe Abstraite (AST) qui représente la structure logique du programme.

Types de Nœuds AST

NoeudProgramme

Racine de l'AST, contient toutes les instructions.

NoeudDeclarationVariable

Déclaration d'une nouvelle variable.

NoeudAffectation

Affectation d'une valeur à une variable existante.

NoeudSi

Structure conditionnelle (si/sinon).

NoeudTantQue

Boucle tant_que.

NoeudFonction

Définition d'une fonction.

NoeudAppel

Appel de fonction.

NoeudExpressionBinaire

Opération binaire (+, -, *, etc.).

NoeudNombre/Chaine/Booleen

Littéraux (valeurs constantes).

Grammaire du Langage

Programme       → Instruction*
Instruction     → Declaration | Affectation | Si | TantQue | 
                  Fonction | Retour | Afficher
Declaration     → 'variable' IDENTIFIANT '=' Expression
Affectation     → IDENTIFIANT '=' Expression
Si              → 'si' Expression Bloc ('sinon' Bloc)? 'fin_si'
TantQue         → 'tant_que' Expression Bloc 'fin_tant_que'
Fonction        → 'fonction' IDENTIFIANT '(' Parametres ')' 
                  Bloc 'fin_fonction'
Expression      → Terme (('+' | '-') Terme)*
Terme           → Facteur (('*' | '/') Facteur)*
Facteur         → NOMBRE | CHAINE | BOOLEEN | IDENTIFIANT | 
                  '(' Expression ')' | AppelFonction

⚙️ Interpréteur - Exécution

Responsabilité

L'interpréteur parcourt l'AST et exécute le code, en maintenant l'état du programme (variables, fonctions, sorties).

Composants de l'Interpréteur

1. Environnement d'Exécution

  • variables : Dictionnaire des variables et leurs valeurs
  • fonctions : Dictionnaire des fonctions définies
  • sortie : Liste des chaînes à afficher
  • entrees_en_attente : Prompts d'entrée requis
  • entrees_fournies : Valeurs fournies par l'utilisateur

2. Exécution des Instructions

Chaque type de nœud AST a une méthode d'exécution spécifique :

  • Déclaration : Ajoute la variable dans l'environnement
  • Affectation : Met à jour la valeur d'une variable
  • Condition : Évalue la condition et exécute le bon bloc
  • Boucle : Répète le bloc tant que la condition est vraie
  • Fonction : Enregistre la définition pour appel ultérieur

3. Évaluation des Expressions

Les expressions sont évaluées récursivement :

  • Littéraux : Retournent leur valeur directement
  • Variables : Récupèrent la valeur dans l'environnement
  • Opérations : Évaluent les opérandes puis appliquent l'opérateur
  • Appels : Exécutent la fonction avec les arguments évalués

Fonctions Intégrées

📤 Entrées/Sorties

afficher(), lire(), input()

🔢 Mathématiques

sqrt(), sin(), cos(), abs(), round()

📝 Chaînes

len(), maj(), min()

🎲 Utilitaires

random(), date(), heure(), annee()

Gestion des Erreurs

L'interpréteur lève des exceptions pour les erreurs d'exécution :

  • Variable non déclarée
  • Variable déjà déclarée
  • Fonction non définie
  • Nombre d'arguments incorrect
  • Division par zéro
  • Type invalide pour une opération

🚀 Déploiement

Configuration Serveur

# Configuration Flask (app.py)
if __name__ == '__main__':
    import os
    port = int(os.environ.get('PORT', '5004'))
    host = os.environ.get('HOST', '0.0.0.0')
    app.run(debug=True, host=host, port=port)

Variables d'Environnement

Variable Défaut Description
PORT 5004 Port d'écoute du serveur
HOST 0.0.0.0 Adresse d'écoute (0.0.0.0 = toutes interfaces)

Déploiement avec Docker

# Construire l'image
docker-compose build

# Lancer le conteneur
docker-compose up -d

# Voir les logs
docker-compose logs -f

# Arrêter
docker-compose down

Déploiement sur Serveur

  1. Cloner le dépôt sur le serveur
  2. Installer Python 3.11+ et les dépendances
  3. Configurer nginx comme reverse proxy
  4. Utiliser gunicorn pour le serveur WSGI en production
  5. Configurer un service systemd pour le démarrage automatique
⚠️ Production

Ne pas utiliser le serveur de développement Flask en production. Utilisez gunicorn ou uwsgi avec nginx.

class NoeudNouveauType:

Dans interpreteur.py :
